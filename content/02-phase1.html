Setup  build.bat step by step ▼
// Step 1, Create the file
In VS Code, in your p01 folder (inside game-dev-exercises), create a new file called build.bat. Make sure it's in the same folder as hello_world.c, not one level up.
// Step 2, Start simple: Hello World build
build.bat, Phase 1 version 
@echo off
set FLAGS=/W4 /WX /Zi /Od
cl %FLAGS% hello_world.c /Fe:hello_world.exe
if %ERRORLEVEL% neq 0 (
    echo BUILD FAILED
    exit /b 1
)
echo BUILD OK
// Step 3, Run it
In your terminal, just type: build That's it. Windows finds build.bat, runs every line inside it, and either reports BUILD OK or BUILD FAILED with the compiler error. Then run your .exe as normal.
// Commit build.bat, not what it makes
build.bat belongs in git. The files it produces (*.exe, *.obj, *.pdb) do not. Phase 4 adds the .gitignore for that.
Predict the Output  2 drills, guess first, then run it ▼
Read the code. Write your prediction on paper, because your head will quietly agree with whatever comes out. Then compile and compare. The ones you get wrong are the ones that teach you something.
1. Two backslashes and two percent signs
#include <stdio.h>

int main(void) {
    printf("C:\\Users\\4samt\\new%%directory\n");
    printf("backslash: \\ percent: %%\n");
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
C:\Users\4samt\new%directory
backslash: \ percent: %
Two doubled characters, two completely different reasons. \\ is the compiler's rule, inside a string literal a backslash starts an escape sequence, so one backslash needs two. That's resolved before your program ever runs.

%% is printf's rule, a percent sign starts a format specifier, so printf needs two to print one. That happens at runtime, inside printf. If you ever print a string that came from somewhere else with printf(text), a stray % in it will make printf go looking for an argument you never passed. Use printf("%s", text).
2. Four printfs, how many lines?
#include <stdio.h>

int main(void) {
    printf("A");
    printf("B\n");
    printf("C\nD");
    printf("E\n");
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer
Three lines from four calls:
AB
C
DE
printf never adds a newline for you. The breaks land exactly where you put \n and nowhere else, which means one printf can produce two lines, and two printfs can produce one.

This is why the command prompt sometimes reappears glued to the end of your last word: you forgot the \n on the final line.
Quiz Yourself  2 questions, answer out loud before revealing ▼
1. You changed the code, hit build, and the output is identical. First thing to check?
Reveal answer
Whether you saved. Look for the dot (●) on the VS Code tab. The compiler reads the file from disk, it has no idea what's on your screen. Ctrl+S, then build. Second thing to check: did the build actually succeed, or did you get BUILD FAILED and then run a stale .exe from the last good compile?
2. What does return 0; at the bottom of main actually tell anyone?
Reveal answer
It tells the operating system the program finished cleanly. 0 means success, anything else means failure. That's the exact same value your build.bat reads as %ERRORLEVEL%, which is how the if %ERRORLEVEL% neq 0 line knows to print BUILD FAILED.

Stuck & Curious  Errors from session 1 + common Phase 1 issues ▼
"'cl' is not recognized as a command"
You're in the wrong terminal. Open a new terminal with Ctrl+`, the VS banner should appear automatically after the settings.json fix. If it doesn't, check that your settings.json was saved correctly and the vcvars32.bat path is correct.
error C2017: unknown escape sequence (the \n error from session 1)
Your \n ended up outside the quotes. It must be INSIDE the string: printf("text\n") not printf("text")\n. \n only means "new line" inside a string. Outside it, the compiler sees a backslash and the letter n, which it doesn't recognise.
I saved but the compiler still uses the old version
Check the tab in VS Code, if there's a dot (●) next to the filename, it's unsaved. Ctrl+S, then compile. The compiler reads from disk. What's on screen doesn't matter until saved.
Program compiles but the window closes immediately
Normal, it runs and exits instantly. Add getchar(); before return 0; to pause. Or run it from the VS Code terminal rather than double-clicking the .exe.
VS Code says "Do you want to install the C/C++ Extension Pack?"
Click Install. Always. This gives you syntax highlighting, error detection, and autocomplete for C. Without it VS Code is just a plain text editor for C files.
Claude Code Prompts  Use these at this phase ▼
Think of AI as a fast contractor and yourself as the architect. You can only catch its mistakes (wrong escapes, wrong format specifiers, wrong return types) if you can read what it wrote, and Phase 1 gives you that.
// Phase 1 prompts, copy and adapt
When you get a compiler error you don't understand
I'm learning C for the first time. I got this compiler error: [paste full error output here]. Explain what it means in plain language, tell me which line caused it and why, then show me exactly how to fix it.
When you want to understand code line by line
I'm a beginner learning C. Explain this code to me line by line, what each part does, why it's there, and what would break if I removed it: [paste code]
When you want AI to write a printf for you
Write a single printf statement in C that prints: "Player: [name] | Score: [score] | HP: [health]" where name is a string, score is an int, and health is an int. Use the correct format specifiers. Nothing else, just the one line.
// The prompting pattern that works at every phase
Be specific
Name the function, the types, the inputs, the outputs. "make it print stuff" → bad. "write printf that prints an int with %d" → good.
Scope it small
Ask for one thing at a time. AI asked for "a whole game" will make architectural decisions you didn't approve. Ask for one function, one file, one fix.
Read before use
Never paste generated code into your project without reading every line. Understand what it does before it becomes your code.
Push back
If the output is more complex than you need, say so: "simplify this, I don't need [X] yet." AI defaults to thorough. You need minimal and understandable.
