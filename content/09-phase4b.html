Starter Code  ascii_runner.c: the skeleton, six TODOs ▼
ascii_runner.c: set SOURCES=ascii_runner.c in build.bat, then run build 
#define WIN32_LEAN_AND_MEAN
#include <windows.h>   // Sleep
#include <conio.h>     // _kbhit, _getch
#include <stdio.h>
#include <string.h>    // memset

#define LANE_LEN   50   // how many characters wide the track is
#define PLAYER_COL 4    // the player never moves sideways. The world moves.
#define MAX_OBS    8    // how many obstacles can exist at once
#define FRAME_MS   33   // ~30 frames a second

// Same enum shape you'll use in Phase 6. Learn it here, reuse it there.
typedef enum {
    STATE_MENU,
    STATE_PLAYING,
    STATE_GAME_OVER
} GameState;

int main(void) {
    char      lane[LANE_LEN + 1];   // +1 for the '\0'. Phase 3 rule.
    int       obs[MAX_OBS];         // column of each obstacle, -1 = empty slot
    GameState state   = STATE_MENU;
    int       running = 1;
    int       ducking = 0;
    int       score   = 0;
    int       frame   = 0;
    int       key     = 0;
    int       i;

    for (i = 0; i < MAX_OBS; i++) {
        obs[i] = -1;
    }

    printf("ASCII RUNNER\n");
    printf("D = duck   R = restart   Q = quit\n");
    printf("Press any other key to start.\n\n");

    while (running) {

        /* --- 1. INPUT: never blocks --------------------------------- */
        key = 0;
        while (_kbhit()) {      // drain everything typed since last frame
            key = _getch();     // no Enter needed, no echo to the screen
        }
        if (key == 'q' || key == 'Q') {
            running = 0;
        }

        /* --- 2. UPDATE: one switch, exactly like Phase 6 ------------- */
        switch (state) {
        case STATE_MENU:
            if (key != 0 && running) {
                state = STATE_PLAYING;
                // TODO 1: reset score, frame, ducking and every obs[] slot.
            }
            break;

        case STATE_PLAYING:
            ducking = 0;
            // TODO 2: if key is 'd' or 'D', set ducking = 1 for this frame.

            // TODO 3: move every live obstacle one column toward the player.
            //         An obstacle that goes below 0 has been dodged: set its
            //         slot back to -1 and add 1 to score.

            // TODO 4: every 20 frames, find a free slot (obs[i] == -1) and put
            //         a new obstacle at column LANE_LEN - 1. Tune the 20 later.

            // TODO 5: the hit test. If any obstacle sits exactly on PLAYER_COL
            //         and ducking is 0, state = STATE_GAME_OVER.

            frame++;
            break;

        case STATE_GAME_OVER:
            // TODO 6: on 'r' or 'R', clear the board and go back to
            //         STATE_PLAYING. Same reset as TODO 1, so write it once,
            //         as a function, and call it from both places.
            break;
        }

        /* --- 3. RENDER: build the whole line, print it ONCE ---------- */
        memset(lane, '.', LANE_LEN);
        lane[LANE_LEN] = '\0';

        for (i = 0; i < MAX_OBS; i++) {
            if (obs[i] >= 0 && obs[i] < LANE_LEN) {
                lane[obs[i]] = '#';
            }
        }
        lane[PLAYER_COL] = ducking ? 'c' : 'A';

        // \r sends the cursor back to column 0 without moving down, so the
        // next print lands on top of this one. That is the entire renderer.
        printf("\r%s  score %-4d", lane, score);
        fflush(stdout);   // push it out now: no '\n', so some terminals would hold it in a buffer

        /* --- 4. WAIT: give the CPU back ----------------------------- */
        Sleep(FRAME_MS);
    }

    printf("\n\nFinal score: %d\n", score);
    return 0;
}
// It compiles clean and runs before you write a single TODO
That's deliberate. Build it, run it, and you'll see an empty track with a stationary A and a score of 0, repainting quietly forever until you press Q. The engine works. The game isn't written yet. Do the TODOs in order, rebuilding after each one, every single one of them produces something visible on screen, which is the fastest feedback loop you've had so far.
Starter Code  Split it: runner.h, runner.c, main.c ▼
// Why now
The game state moves into a Runner struct, the switch and render step become functions that take a Runner*, and main shrinks to the four-step loop. Same game, only the shape changes.
runner.h, what exists (no bodies, no variables) 
#pragma once

#define LANE_LEN   50
#define PLAYER_COL 4
#define MAX_OBS    8

typedef enum { STATE_MENU, STATE_PLAYING, STATE_GAME_OVER } GameState;

typedef struct {
    int       obs[MAX_OBS];   // column of each obstacle, -1 = empty slot
    GameState state;
    int       ducking;
    int       score;
    int       frame;
} Runner;

void runner_reset(Runner* r);            // TODO 1 and TODO 6, written once
void runner_update(Runner* r, int key);  // the whole switch
void runner_render(const Runner* r);     // builds the lane and prints it once
main.c, just the loop 
#define WIN32_LEAN_AND_MEAN
#include <windows.h>   // Sleep: only main.c needs Windows now
#include <conio.h>
#include <stdio.h>
#include "runner.h"

#define FRAME_MS 33

int main(void) {
    Runner r;
    int    key;

    runner_reset(&r);
    r.state = STATE_MENU;

    for (;;) {
        key = 0;
        while (_kbhit()) key = _getch();   // 1. input
        if (key == 'q' || key == 'Q') break;

        runner_update(&r, key);              // 2. update
        runner_render(&r);                   // 3. render
        Sleep(FRAME_MS);                       // 4. wait
    }

    printf("\n\nFinal score: %d\n", r.score);
    return 0;
}
build.bat, two source files, one word 
@echo off
set FLAGS=/std:c17 /W4 /WX /Zi /Od /external:anglebrackets /external:W0
set SOURCES=main.c runner.c

cl %FLAGS% %SOURCES% /Fe:runner.exe
if %ERRORLEVEL% neq 0 (
    echo  BUILD FAILED.
    exit /b 1
)
echo  BUILD OK: runner.exe
// runner.c is yours to write
Start it with #include "runner.h", <stdio.h> and <string.h>, then move code in from ascii_runner.c: the reset into runner_reset, the switch into runner_update, the render step into runner_render (the lane buffer becomes a local variable in there). Every score becomes r->score. Build after each function you move, not at the end.

Stuck & Curious  Real-time terminal problems ▼
Input feels laggy, I press duck and it happens a moment later, or several times
Two separate causes. First, your reaction window is one frame long, so at Sleep(33) a key can wait up to 33 ms before the loop even looks. Lower FRAME_MS to 16 and it halves. Second, holding a key down makes Windows repeat it, which stuffs dozens of characters into the buffer, if you only call _getch() once per frame you're working through a backlog that gets further behind every frame. That's what the while (_kbhit()) loop is for: drain the buffer completely each frame and keep only the last key.
Flicker, new lines, nothing showing until you quit, Sleep timing and LNK2005 are answered in the concept pages' Q&A: see Redrawing in place: \r and fflush, Frame timing with Sleep, and Multiple files and LNK2005.

Mixed Review  one from Phase 03, one from Phase 3.5 ▼
Two questions from earlier phases. Remembering something after a gap is what makes it stay, answer out loud first.
1. [Phase 03] The lane is char lane[LANE_LEN + 1]. What's the last valid index, and what is the +1 for?
Reveal answer
The last index is LANE_LEN itself, the array has LANE_LEN + 1 boxes, numbered from 0. The extra box holds the '\0', so %s knows where the track ends. Without it, printf would run on into whatever memory comes next.
2. [Phase 3.5] You write void runner_update(Runner r, int key), no asterisk, and it compiles. What does the game do?
Reveal answer
Nothing moves, ever. The function gets a copy of the Runner, updates the copy, and the copy is thrown away at the closing brace. Your real r in main never changes. It's the photocopy problem again, which is why every function that changes the game takes a Runner*.
