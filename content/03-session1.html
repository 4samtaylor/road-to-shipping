Concepts Discovered  Everything explored this session ▼
// Escape sequences — special characters inside strings
A backslash inside a string tells the compiler "the next character is special." You discovered several this session:

\n — new line (like pressing Enter). Must be inside the quotes.
\r — carriage return. Moves the cursor back to the start of the current line WITHOUT moving down. This is why "Lets" disappeared — \r moved the cursor back, then " party up!" overwrote it. Old terminal behavior from typewriter days.
\\ — prints a single literal backslash. You need two because one backslash starts an escape sequence. \\ says "escape sequence that means backslash."
%% — prints a literal % sign inside printf. Single % starts a format specifier (%d, %f etc.) so you need two to print the symbol itself.
\t — tab character (you'll see this one soon)

The rule: inside a printf string, backslash and % are special. To print them literally you double them: \\ and %%.
// Functions — you wrote your first one
You wrote a function called var that takes a float and returns an int. This is the basic anatomy of every function you'll ever write:

return_type function_name ( parameter_type parameter_name ) { ... }

int var(float x) means: "a function named var that accepts a float called x and returns an int."

You called it with var(1.8f) — the f suffix tells the compiler "this is a float literal, not a double." Without the f, 1.8 is a double by default, which caused the C4305 truncation warning.
// Type conversion — what actually happened with 1.8 → 1
This is one of the most important things to understand in C.

Your function receives 1.8 as a float and tries to return it as an int. C allows this but truncates — it chops off everything after the decimal point. Not rounded. Just dropped.

1.8f → int = 1 (not 2)
7.9f → int = 7 (not 8)
-1.8f → int = -1 (towards zero, not down)

This is why the compiler warned you with C4244: possible loss of data. It's not an error by default — C will do it — but the compiler knows you might not have intended it. The warning was correct. Always read warnings.

You observed this directly: passing 1.8f printed I am 1 years old, not 1.8.
// Format specifiers — %d %f %s and when to use each
Format specifiers are placeholders inside a printf string that get replaced by values:

%d — integer (int). Prints a whole number.
%f — float or double. Prints a decimal number (default 6 decimal places).
%.2f — float with exactly 2 decimal places.
%s — string. Prints a sequence of characters.
%c — single character.

The type must match. Using %d to print a float doesn't convert it — it reads the wrong bytes and prints garbage. The compiler warned about this too.
// Comments — two styles
You used both comment styles this session:

// single line comment — everything after // on that line is ignored
/* multi line comment */ — everything between /* and */ is ignored, can span lines

The compiler ignores comments entirely. They exist only for humans. You discovered this when you commented out the //type variable name = value; lines — they stopped causing errors because the compiler never saw them.
// build.bat — what you set up and why it matters
You built and ran build.bat successfully. Key things learned:

Paste into the editor, not the terminal. Pasting into the terminal runs the lines as commands. Paste into the build.bat file tab in VS Code.

@echo off silences command echo. Without it the terminal prints each command before running it.

%ERRORLEVEL% is a Windows variable set by every program on exit. 0 = success. Anything else = failure. The if block catches failed compiles and prints BUILD FAILED so you don't accidentally run a stale .exe.

/W4 and /WX — turn on strict warnings and treat them as errors. You encountered this firsthand: /WX made the C4244 warning stop the build entirely. This is intentional. Add these flags once your code is clean — they keep it that way.
Fix Before Next Session  2 remaining warnings ▼
C4244: 'return' — conversion from 'float' to 'int', possible loss of data
Your var() function accepts a float and returns an int. The fix is to match the return type to what you're actually returning:

Change int var(float x) to float var(float x)

Then update the printf to use %f instead of %d since you're now returning a float:
printf("I am %f years old\n", var(1.8f));

Or if you want to keep it as int (intentional truncation), cast explicitly to silence the warning:
return (int)x; — this tells the compiler "yes, I know, I'm doing this on purpose."
C4305: truncation from 'double' to 'float'
When you write 1.8, C treats it as a double (64-bit). Your function expects a float (32-bit). Fix: add the f suffix to tell the compiler it's already a float:

var(1.8f) instead of var(1.8)

You already had this — just make sure the f is there.
