Concepts First  Data Types — read this before the exercises ▼
// The core rule
C is statically typed — every variable's type must be declared upfront and cannot change. You experienced this in session 1: returning a float from an int function produced a warning. The compiler caught the mismatch immediately. That's static typing working in your favour.
int — whole numbers
4 bytes  ·  specifier: %d  ·  range: ±2.1 billion
int age = 20;
int score = -50;
int frame = 0;
printf("%d", age); // 20
Use for: health, score, frame count, enemy count
float — decimal numbers
4 bytes  ·  specifier: %f  ·  ~7 digits precision
float speed = 2.5f; // f suffix = float
float x = 100.0f;
printf("%f", speed);   // 2.500000
printf("%.2f", speed); // 2.50
Use for: position x/y, velocity, speed, timers
double — high precision decimal
8 bytes  ·  specifier: %lf  ·  ~15 digits precision
double pi = 3.14159265358979;
// 1.8 without f suffix IS a double
// That caused the C4305 warning in session 1
printf("%.5lf", pi); // 3.14159
Float is fine for games. Double for high precision physics.
char — single character
1 byte  ·  specifier: %c  ·  stored as ASCII number
char grade = 'A'; // single quotes
char input = '\0'; // null = nothing yet
printf("%c", grade); // A
printf("%d", grade); // 65 (ASCII number)
Use for: key input, individual characters, small flags
void — no value
Represents "nothing." Used for functions that don't return a value. When you see void as a return type, the function is doing something (moving, printing, updating) rather than calculating a result to hand back.
void player_move(Player* p) {
    p->x += 5;
    // no return needed
}
int get_score() {
    return 100; // returns a value
}

// Type conversion — what you discovered in session 1
float → int: truncated, not rounded. 1.8 → 1. 7.9 → 7.
double → float: precision reduced. Caused C4305 in session 1.
int → float: safe — no data lost. Use an explicit cast to convert intentionally:
float x = 1.8f;
int n = (int)x; // explicit cast — silences C4244, means "I know what I'm doing"
printf("%d", n); // 1
// Integer division & casting — where the maths quietly goes wrong
int / int is an int. The fraction is thrown away before you ever see it: 7 / 2 is 3, and 1 / 2 is 0. The type of an expression is decided by what goes into it, not by the variable you store it in — so float f = 7 / 2; gives you 3.0, not 3.5.

% is the leftover. 7 % 2 is 1. You'll use it constantly: n % 2 == 0 means even, and (i + 1) % count wraps back to 0 at the end of a list.

Cast before you divide, not after:
float half = (float)7 / 2;     // 3.5 — 7 becomes 7.0f first, so the division is float
float oops = (float)(7 / 2);   // 3.0 — the int division already happened inside the brackets
int   pct  = hp * 100 / max_hp; // multiply first: 30 * 100 / 120 = 25, but 30 / 120 * 100 = 0

printf("int:    %d bytes\n", sizeof(int));
printf("float:  %d bytes\n", sizeof(float));
printf("double: %d bytes\n", sizeof(double));
printf("char:   %d bytes\n", sizeof(char));

Explain Like I'm New  Loops and conditionals, in plain English ▼
// A loop is the engine of every game
In session 1 your program ran once, top to bottom, and exited. A game can't do that. A game has to keep going — draw, listen, move, draw again — about 60 times every second, until the player quits. That repetition is a loop. The frame loop is the single most important structure in your game. 
while (running) {   // keep going until this stops being true
    // read input   → what did the player press?
    // update       → move things, check collisions, subtract health
    // draw         → put the new picture on screen
}                    // then straight back to the top. One pass = one frame.
while — "keep doing this until the condition goes false." Use it when you don't know how many times: the game runs until the player dies or quits.
for — "do this an exact number of times." Use it when you do know: spawn 10 enemies, print 5 high scores, step through every bullet.
Same machinery, different question. while = until something changes. for = a known count.
// if / else is the decision gate
An if asks a yes/no question and only runs its block when the answer is yes. Everything a game "decides" is built out of these. Did the bullet hit? Is health at zero? Is the guess too high? 
if (health <= 0) {
    alive = 0;              // gate opened — run this
} else if (health < 25) {
    printf("Low health!\n"); // first gate was shut, this one opened
} else {
    // every gate above was shut — this is the fallback
}
C checks the gates in order and stops at the first one that's true. The rest never run. So put the most specific test first.
= assigns. == compares. if (health = 0) sets health to 0 and then asks "is 0 true?" — always false, and you've silently wiped the variable. /W4 catches most of these. Not all.

frame_loop.c — your first game loop 
#include <stdio.h>

int main() {
    int frame = 0;
    char input = '\0';

    printf("Frame loop started. Type a character + Enter to stop.\n\n");

    while (input != 'q') {
        printf("Frame: %d\n", frame);
        frame++;

        // Read one character from the user
        // Note: scanf waits for Enter — that's expected for now

Starter Code  random_number.c — how the computer picks 1–100 ▼
random_number.c — you need this for the guessing game 
#include <stdio.h>
#include <stdlib.h>   // rand() and srand() live here — a different toolbox to stdio.h
#include <time.h>     // time() lives here

int main(void) {
    int secret;

    // Seed the generator ONCE, at the top of main. Never inside a loop.
    // time(NULL) = seconds since 1970 — a different number every run.
    // The (unsigned int) cast is deliberate: time() hands back a time_t,
    // srand() wants an unsigned int. Same C4244 lesson from session 1.
    srand((unsigned int)time(NULL));

    // rand() gives a big whole number. % 100 keeps only the remainder
    // after dividing by 100, which is 0–99. Add 1 to shift it to 1–100.
    secret = rand() % 100 + 1;

    printf("Secret number: %d\n", secret);

    // TODO: run it 3 times. Different number each time? Good.
    // TODO: comment out the srand line and run it 3 more times. Watch what happens.
    // TODO: change the range to 1-10, then to 1-1000.

    return 0;
}
// Seeding — the one sentence that explains it
rand() isn't actually random. It's a recipe that turns one number into the next, forever — so the same seed always produces the same sequence. Without srand the seed defaults to 1 every single run, and your guessing game picks the identical "random" number every time you launch it. Seeding with the clock means the recipe starts somewhere new each run.

Seed once. If you call srand(time(NULL)) inside your guess loop, every call within the same second reseeds with the same value and rand() hands you the same number back.
Stuck & Curious  Common errors at this stage ▼
scanf seems to skip input or read the wrong character
The space before %c in scanf(" %c", &input) is intentional. It eats the leftover newline from pressing Enter. Without it, scanf captures Enter instead of your character. One of the most famous C beginner traps — remember it forever.
My while loop runs forever and I can't stop it
Press Ctrl+C in the terminal to kill it. Then check: is your condition ever becoming false? Add a printf inside the loop to see what input is reading each iteration. Also confirm you're using != not = in your while condition.
When should I use for vs while?
for = you know how many times (counting frames, iterating 10 enemies). while = you loop until something changes (waiting for input, game running until player dies). In your game: the main game loop is while. Spawning 5 enemies in a row is for.
I don't understand what & does in scanf
The & gives scanf the memory address of your variable — where it lives — so it can write directly into it. Without &, you pass the current value (useless to scanf). Think of it as giving someone your house address vs telling them what's inside. scanf needs the address to deliver the new value.
// Curious — the "why" questions
Why does rand() % 100 pick small numbers slightly more often?
On MSVC, rand() returns 0 to 32767 — that's 32,768 possible values. 32,768 doesn't divide evenly by 100: it's 327 full rounds plus 68 left over. So 0–67 each come up 328 ways and 68–99 only 327 ways. For a guessing game nobody will ever notice. It's called modulo bias, and it's why real games use better random generators.
Why does C have both for and while, if for can do everything?
Because code is read more than it's written. for (;running;) is exactly the same as while (running), but a for tells the reader "this counts", and a while tells them "this waits for something to change" before they read a single line inside. Choosing the right one is a message to your future self.
Why does printf("%.10f", 0.1f + 0.2f) not print 0.3000000000?
Floats are stored in binary, and 0.1 has no exact binary form — the same way 1/3 has no exact decimal form (0.3333…). You get the closest value the float can hold, and the tiny errors add up. That's why you never write if (x == 0.3f) for a float. For games it's fine: nobody can see a millionth of a pixel.

Predict the Output  4 drills — guess first, then run it ▼
// These four are the classic traps of this phase
Every one of them compiles clean and runs fine. That's what makes them dangerous — nothing warns you, the program just quietly does something other than what you meant. Prediction on paper first, then run.
1. Integer division
#include <stdio.h>

int main(void) {
    int a = 7;
    int b = 2;

    printf("%d\n", a / b);
    printf("%d\n", a % b);
    printf("%.2f\n", (float)a / b);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
3
1
3.50
Two ints divided give an int. The remainder isn't rounded up, it's discarded — 7/2 is 3, not 4. % hands you the part that was thrown away.

Casting one side to float is enough: the other side gets converted to match, and the whole expression becomes floating point. The game bug this causes: a health bar drawn as health / max_health with two ints is 0 for every value below full, so the bar is empty until the instant it's full.
2. Off by one — how many times does this run?
#include <stdio.h>

int main(void) {
    int i;

    for (i = 0; i <= 5; i++) {
        printf("%d ", i);
    }
    printf("\n");
    printf("i ended at %d\n", i);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
0 1 2 3 4 5
i ended at 6
Six numbers, not five. <= lets the body run once more than the number suggests, and it's the single most common loop bug there is.

The second line is the other half of the lesson: when the loop exits, i is one past the last value it used, because the loop only stops after the test has already failed. Both of these matter enormously in Phase 3, where i is an array index and one extra step reads memory that isn't yours.
3. = versus == — both of these are legal C
#include <stdio.h>

int main(void) {
    int health = 100;
    int test;

    test = (health == 50);
    printf("A: test %d, health %d\n", test, health);

    test = (health = 50);
    printf("B: test %d, health %d\n", test, health);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
A: test 0, health 100
B: test 50, health 50
== asks a question and hands back 1 or 0. = performs an assignment and hands back the value it just assigned. Line B did two things at once: it wrecked health, and it produced 50.

Now picture line B inside an if. The condition is 50, anything non-zero is true in C, so the branch always runs and your health is gone. That's the classic.

Written outside an if like this, it's ordinary legal C and nothing warns. Put it in a condition and MSVC at /W4 raises C4706 — assignment within a conditional expression — and /WX turns that into a stopped build. That's your flags doing the job you turned them on for.
4. A char is a number wearing a costume
#include <stdio.h>

int main(void) {
    char c = 'A';

    printf("%c %d\n", c, c);
    c = (char)(c + 2);
    printf("%c %d\n", c, c);
    printf("%d\n", 'a' - 'A');
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
A 65
C 67
32
A char is a one-byte integer holding an ASCII code. 'A' is 65. Add 2 and you have 67, which %c shows as C and %d shows as 67 — same byte, two ways of looking at it. The specifier decides what you see, not the data.

The (char) cast is there because c + 2 is an int, and putting an int back in a char box is the same narrowing that produced C4244 in session 1. And 'a' - 'A' being exactly 32 is the whole trick behind flipping letter case by hand.
Quiz Yourself  5 questions — answer out loud before revealing ▼
1. Why is there a space in scanf(" %c", &input)?
Reveal answer
The space tells scanf to skip over any leftover whitespace first — including the Enter key still sitting in the input buffer from the previous read. Without it, scanf grabs that newline as your character and the loop appears to skip a turn. And the & hands scanf the address of your variable so it can write into it, rather than a copy of its value.
2. Spawning 10 enemies vs running the game until the player quits — which gets a for and which gets a while?
Reveal answer
10 enemies is a for — you know the count before you start. The game running until quit is a while — you have no idea how many frames that will be, only what makes it stop. Known count = for. Until something changes = while.
3. You delete the srand line from your guessing game. What happens when you run it three times?
Reveal answer
The same secret number all three times. rand() is a recipe that walks from one number to the next, and without srand it always starts from seed 1 — same seed, same sequence, same first number. Seeding with time(NULL) starts the recipe somewhere new every run.
4. What range does rand() % 100 + 1 produce, and what would you write for 1–6?
Reveal answer
1 to 100. % 100 keeps the remainder after dividing by 100, which is 0–99, and + 1 shifts the whole range up by one. For a dice roll: rand() % 6 + 1. The pattern is rand() % (how many) + (lowest).
5. What's wrong with while (input = 'q')?
Reveal answer
One equals sign assigns, two compares. That line stuffs 'q' into input and then asks "is 'q' true?" — it is (any non-zero value is true), so the loop runs forever and your input variable is destroyed on every pass. You wanted while (input != 'q'). /W4 flags most of these, which is exactly why you turned it on.

Mixed Review  two from Phase 01 ▼
Two questions from earlier phases. Remembering something after a gap is what makes it stay — answer out loud first.
1. [Phase 01] What does printf("%d%%\n", 50); print?
Reveal answer
50%. %d is replaced by 50, and %% is printf's way of printing one percent sign — a single % would start another format specifier.
2. [Phase 01] build says BUILD FAILED, you run game.exe anyway and it works perfectly. What did you just run?
Reveal answer
The .exe from your last successful build. A failed compile doesn't delete the old file, it just doesn't replace it. That's why build.bat exits as soon as %ERRORLEVEL% isn't 0 — so you notice before you test old code.
