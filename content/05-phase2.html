Starter Code  frame_loop.c ▼
frame_loop.c, your first game loop 
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>

int main() {
    int frame = 0;
    char input = '\0';

    printf("Frame loop started. Type a character + Enter to stop.\n\n");

    while (input != 'q') {
        printf("Frame: %d\n", frame);
        frame++;

        // Read one character from the user
        // Note: scanf waits for Enter — that's expected for now
        scanf(" %c", &input);
    }

    printf("\nYou entered: %c\n", input);
    printf("Total frames run: %d\n", frame);

    // TODO: Change 'q' to a different quit character

    // TODO: Print "HALFWAY!" when frame == 50

    return 0;
}

#include <stdio.h>
#include <stdlib.h>   // rand() and srand() live here — a different toolbox to stdio.h
#include <time.h>     // time() lives here

int main(void) {
    int secret;

    // Seed the generator ONCE, at the top of main. Never inside a loop.
    // time(NULL) = seconds since 1970 — a different number every run.
    // The (unsigned int) cast is deliberate: time() hands back a time_t,
    // srand() wants an unsigned int. Same C4244 lesson from session 1.

    // after dividing by 100, which is 0–99. Add 1 to shift it to 1–100.
    secret = rand() % 100 + 1;

Predict the Output  4 drills, guess first, then run it ▼
// Four classic traps
Every one compiles clean and runs fine, so nothing warns you. Prediction on paper first, then run.
1. Truncation: the C4244 from session 1, on purpose this time
#include <stdio.h>

int main(void) {
    float x = 1.8f;
    int   n = (int)x;

    printf("%d\n", n);
    printf("%.1f\n", x);
    printf("%d\n", (int)9.99f);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
1
1.8
9
float to int truncates toward zero. It does not round. 1.8 becomes 1 and 9.99 becomes 9. The fraction is thrown in the bin, not weighed up.

This is exactly what int var(float x) { return x; } was doing silently in session 1, and why the compiler raised C4244. Note that x itself is untouched, it still prints 1.8. The (int) cast doesn't change the behaviour one bit; it changes the conversation with the compiler from "you might not have meant this" to "I meant it."
2. Off by one, how many times does this run?
#include <stdio.h>

int main(void) {
    int i;

    for (i = 0; i <= 5; i++) {
        printf("%d ", i);
    }
    printf("\n");
    printf("i ended at %d\n", i);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
0 1 2 3 4 5
i ended at 6
Six numbers, not five. <= lets the body run once more than the number suggests, and it's the single most common loop bug there is.

The second line is the other half of the lesson: when the loop exits, i is one past the last value it used, because the loop only stops after the test has already failed. Both of these matter enormously in Phase 3, where i is an array index and one extra step reads memory that isn't yours.
3. = versus ==, both of these are legal C
#include <stdio.h>

int main(void) {
    int health = 100;
    int test;

    test = (health == 50);
    printf("A: test %d, health %d\n", test, health);

    test = (health = 50);
    printf("B: test %d, health %d\n", test, health);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
A: test 0, health 100
B: test 50, health 50
== asks a question and hands back 1 or 0. = performs an assignment and hands back the value it just assigned. Line B did two things at once: it wrecked health, and it produced 50.

Now picture line B inside an if. The condition is 50, anything non-zero is true in C, so the branch always runs and your health is gone. That's the classic.

Written outside an if like this, it's ordinary legal C and nothing warns. Put it in a condition and MSVC at /W4 raises C4706, assignment within a conditional expression, and /WX turns that into a stopped build. That's your flags doing the job you turned them on for.
4. A char is a number wearing a costume
#include <stdio.h>

int main(void) {
    char c = 'A';

    printf("%c %d\n", c, c);
    c = (char)(c + 2);
    printf("%c %d\n", c, c);
    printf("%d\n", 'a' - 'A');
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
A 65
C 67
32
A char is a one-byte integer holding an ASCII code. 'A' is 65. Add 2 and you have 67, which %c shows as C and %d shows as 67, same byte, two ways of looking at it. The specifier decides what you see, not the data.

The (char) cast is there because c + 2 is an int, and putting an int back in a char box is the same narrowing that produced C4244 in session 1. And 'a' - 'A' being exactly 32 is the whole trick behind flipping letter case by hand.
Quiz Yourself  3 questions, answer out loud before revealing ▼
1. Why is there a space in scanf(" %c", &input)?
Reveal answer
The space tells scanf to skip over any leftover whitespace first, including the Enter key still sitting in the input buffer from the previous read. Without it, scanf grabs that newline as your character and the loop appears to skip a turn. And the & hands scanf the address of your variable so it can write into it, rather than a copy of its value.
2. Spawning 10 enemies vs running the game until the player quits, which gets a for and which gets a while?
Reveal answer
10 enemies is a for, you know the count before you start. The game running until quit is a while, you have no idea how many frames that will be, only what makes it stop. Known count = for. Until something changes = while.
3. A health bar is drawn from health / max_health, both ints. It stays empty until health is full. Why, and what are two ways to fix it?
Reveal answer
Int divided by int is an int, so 60 / 100 is 0. Cast one side before the division: (float)health / max_health. Or multiply first: health * 100 / max_health gives a whole-number percentage. Casting after, as in (float)(health / max_health), is too late.
Mixed Review  two from Phase 01 ▼
Two questions from earlier phases. Remembering something after a gap is what makes it stay, answer out loud first.
1. [Phase 01] What does printf("%d%%\n", 50); print?
Reveal answer
50%. %d is replaced by 50, and %% is printf's way of printing one percent sign, a single % would start another format specifier.
2. [Phase 01] build says BUILD FAILED, you run game.exe anyway and it works perfectly. What did you just run?
Reveal answer
The .exe from your last successful build. A failed compile doesn't delete the old file, it just doesn't replace it. That's why build.bat exits as soon as %ERRORLEVEL% isn't 0, so you notice before you test old code.

Stuck & Curious  Common errors at this stage ▼
scanf seems to skip input or read the wrong character
The space before %c in scanf(" %c", &input) is intentional. It eats the leftover newline from pressing Enter. Without it, scanf captures Enter instead of your character. One of the most famous C beginner traps, remember it forever.
My while loop runs forever and I can't stop it
Press Ctrl+C in the terminal to kill it. Then check: is your condition ever becoming false? Add a printf inside the loop to see what input is reading each iteration. Also confirm you're using != not = in your while condition.

// The habit for this phase
Never ask AI to "build the feature". Ask for the structure without the implementation: the skeleton with comments, not the filled-in version. You write the logic, which is where the learning happens. The game loop (input, update, draw) is yours to design.
Get structure, not implementation (the scaffolding technique)

Give me just the loop structure with TODO comments where I need to fill in logic, don't write the actual logic for me. I want to do that myself.
When you've written it yourself and want a review

When you don't understand why your loop behaves wrong
I have a while loop in C that's behaving unexpectedly. Expected: [describe]. Actual: [describe]. Here's the code: [paste]. Don't fix it for me, walk me through what's actually happening each iteration so I can find the problem myself.
When choosing between for and while
I'm building [describe the feature] in C. Should I use a for loop or a while loop here, and why? What would happen if I used the other one? I want to understand the tradeoff, not just get an answer.
