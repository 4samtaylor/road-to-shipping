Starter Code  player.h + player.c ▼
player.h, the declaration (what exists) 
#pragma once
#include <stdbool.h>

// A struct groups related data together
// Think of it as a blueprint for a game object
typedef struct {
    float x;
    float y;
    int   health;
    bool  alive;
} Player;

// Function declarations — the "what" without the "how"
Player player_create(float start_x, float start_y);
void   player_move(Player* p, float dx, float dy);
void   player_take_damage(Player* p, int amount);
void   player_print(Player* p);
player.c, the definitions (the actual code) 
#include "player.h"
#include <stdio.h>

Player player_create(float start_x, float start_y) {
    Player p;
    p.x      = start_x;
    p.y      = start_y;
    p.health = 100;
    p.alive  = true;
    return p;
}

// Player* means "a pointer to a Player" — we pass by pointer
// so the function can MODIFY the original, not a copy
void player_move(Player* p, float dx, float dy) {
    p->x += dx;
    p->y += dy;
}

void player_take_damage(Player* p, int amount) {
    p->health -= amount;
    if (p->health <= 0) {
        p->health = 0;
        p->alive = false;
    }
}

void player_print(Player* p) {
    printf("Player pos: (%.1f, %.1f) health: %d alive: %s\n",
           p->x, p->y, p->health,
           p->alive ? "yes" : "no");
}

Practice this  Watch hero change from a function that never names it ▼
// Watch a pointer change, live
The mental models were metaphors. This is the thing itself. Ten minutes, once your main.c (Build Spec) creates hero and damages it with player_take_damage(&hero, ...).
1
Run build. Make sure it succeeded before you touch F5.
2
Open player.c. Put the cursor on the first line inside player_take_damage and press F9.
3
Press F5. The program starts, then freezes on that line with a yellow arrow the first time damage is dealt.
4
Open the Watch panel and add three expressions: p, *p, and p->health.
5
Look at them before you step. p is a number like 0x00affc10, that's the address, the piece of paper with the house number on it. *p expands into the whole Player. p->health is one field inside it.
6
Press F10 once. Watch p->health drop. Nothing in this function is named "hero", and hero's health just changed anyway. That is what a pointer does, and you are watching it happen.
7
Now go up to main, add &hero to the Watch panel, and compare it to p. Same number. Same house.
Do the same thing with the photocopy version from the Break it experiments on the Build page, player_move(Player p, ...), no asterisk. Watch p.x change inside the function, then step out and watch hero.x sit there untouched. The copy dying at the closing brace, on screen.

// Design the interface first, then ask for the body
When you ask AI for a function, you are choosing its name, what it takes in, what it returns and what it changes. If you don't say, AI invents them, and the invention may not match your game. So write the declaration yourself first, like void player_heal(Player* p, int amount);, and ask AI to fill in only the body. Predict the Output  2 drills: guess first, then run it ▼
Predict on paper, run, compare. Then step through each one with a breakpoint and the Watch panel open.
1. Three spellings, one box
#include <stdio.h>

typedef struct {
    int health;
} Player;

int main(void) {
    Player  hero;
    Player* p = &hero;

    hero.health = 100;
    p->health   -= 30;
    (*p).health -= 20;

    printf("%d %d\n", hero.health, p->health);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer
50 50

p->health is nothing more than shorthand for (*p).health. Both mean "go to the address, then take the health field." And hero.health is that same field reached the direct way.

Three spellings, one box in memory. The two printed numbers are identical because there is only one Player in this entire program, p is a note with hero's address written on it, not a second player.
2. Truncation, now living inside a struct
#include <stdio.h>

typedef struct {
    float x;
    int   steps;
} Player;

int main(void) {
    Player hero;
    hero.x     = 0.0f;
    hero.steps = 0;

    hero.x     += 2.7f;
    hero.steps += (int)2.7f;

    printf("x %.1f  steps %d\n", hero.x, hero.steps);
    printf("%d\n", (int)(hero.x * 2.0f));
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
x 2.7  steps 2
5
The float field keeps its fraction. The int field throws it away, truncated toward zero, so 2.7 adds 2 and 5.4 comes out 5. Session 1's C4244 lesson, now happening one field away from another field that behaves differently.

The game bug: keep a position as an int and every fractional movement is lost, so a player moving 2.7 per frame actually moves 2 and drifts further behind the truth every frame. Positions stay float. You truncate once, at the moment you draw, and never store the result back.
Mixed Review  two from earlier phases, one from this one ▼
Three questions, two from earlier phases. Remembering something after a gap is what makes it stay, answer out loud first.
1. [Phase 03] What's wrong with #define MAX_SCORES 5;?
Reveal answer
The semicolon. #define is find-and-replace, so every MAX_SCORES becomes 5;, and int scores[MAX_SCORES]; turns into int scores[5;];. The error points at the array line, not the define, which is what makes it nasty.
2. [Phase 02] What do 7 % 3 and -7 / 2 give you in C?
Reveal answer
1 and -3. Integer division truncates toward zero, so -3.5 becomes -3, not -4. Same rule as casting a float to an int, it chops, it never rounds.
3. In one sentence each: what does &x give you, and what does *p give you?
Reveal answer
&x gives the address where x lives, the house number, not what's inside. *p goes to the address p is holding and reads what's there. Same & you were already using in scanf(" %c", &input) back in Phase 2, you were handing scanf an address the whole time.

Break it  Three experiments, on purpose ▼
After each build works, break it once and read what the tools say. Errors you have met on purpose are less scary later.
The photocopy. Change player_move(Player* p, ...) to player_move(Player p, ...), swap the arrows for dots so it compiles, and run it. The player refuses to move.
The double include. Delete #pragma once from player.h and #include "player.h" twice in main.c. Predict the failure, then read the real error (C2011).
The missing file. Take player.c out of the SOURCES line and build. Read the LNK2019 error and say why the compiler was happy but the linker wasn't.
