Starter Code  arrays.c, every line explained ▼
arrays.c, add it to build.bat, then run build 
#include <stdio.h>
#include <string.h>   // strlen, strcmp and strcspn all live in this toolbox

#define NAME_LEN 32   // how many chars the buffer holds, INCLUDING the '\0'
                     // #define is a find-and-replace done before compiling.

int main(void) {
    // An array is a row of numbered boxes, all the same type.
    int  scores[5] = { 40, 95, 12, 78, 63 };
    char name[NAME_LEN];   // 32 char boxes. Right now they hold garbage.
    int  count;
    int  max;
    int  i;

    // sizeof(the whole array) / sizeof(one box) = how many boxes.
    // sizeof hands back a size_t, so cast it, same move as (int)x in session 1.
    count = (int)(sizeof(scores) / sizeof(scores[0]));

    // Boxes are numbered from 0, so the last one is count - 1.
    // i < count, never i <= count. scores[5] does not exist.
    for (i = 0; i < count; i++) {
        printf("scores[%d] = %d\n", i, scores[i]);
    }

    // Assume box 0 wins, then let every other box challenge it.
    max = scores[0];
    for (i = 1; i < count; i++) {   // starts at 1, 0 is already the champion
        if (scores[i] > max) {
            max = scores[i];
        }
    }
    printf("Highest: %d\n", max);

    // TODO 1: copy that loop and turn it into a min loop. Watch the > vs <.

    // A C string is just a char array that ends with a '\0'.
    // fgets reads at most NAME_LEN - 1 chars and writes the '\0' itself,
    // so it can never run off the end of the buffer. scanf("%s") can.
    printf("What's your name? ");
    if (fgets(name, NAME_LEN, stdin) != NULL) {
        // fgets keeps the Enter key as a '\n' on the end. Chop it off by
        // writing a '\0' over it, strcspn finds where the '\n' is.
        name[strcspn(name, "\n")] = '\0';
    } else {
        name[0] = '\0';   // read failed, make it an empty string, not garbage
    }

    // strlen counts characters up to the '\0'. It does NOT count the '\0'.
    // It returns a size_t, so cast it to keep %d honest under /W4 /WX.
    printf("Hi %s. That is %d characters.\n", name, (int)strlen(name));

    // strcmp returns 0 when the two strings are EQUAL. Read that twice.
    if (strcmp(name, "Sam") == 0) {
        printf("Good name.\n");
    }

    // TODO 2: print the name one char at a time with a for loop and %c.
    // TODO 3: printf("%d\n", name[0]);, why does that print a number?
    // TODO 4: print strcmp(name, "Sam") directly with %d for a match and a
    //         mismatch. Three different answers. Work out what they mean.

    return 0;
}
// The high-score build, the shape of it, not the answer
Five ints, sorted highest first. A new score arrives. Walk the array to find the first slot the new score beats. Everything from that slot down shifts one place toward the end, and the last one falls off. Then drop the new score into the hole.

The trick is the direction you shift. If you copy forwards you'll overwrite the value you were about to move. Work out which way to walk before you write it. Get it wrong once on purpose so you can see what the output does.

saving and loading, fopen, fprintf, fscanf, fclose (King ch 22) 
#define _CRT_SECURE_NO_WARNINGS   // first line of the file, before any #include (see below)
#include <stdio.h>

void save_scores(char names[][NAME_LEN], int scores[], int count) {
    FILE* f = fopen("scores.txt", "w");   // "w" = write: creates the file, or wipes it
    int i;
    if (f == NULL) { fprintf(stderr, "Couldn't save scores\n"); return; }
    for (i = 0; i < count; i++) {
        fprintf(f, "%s %d\n", names[i], scores[i]);   // printf, but into the file
    }
    fclose(f);   // always close, the last writes may not reach the disk until you do
}

int load_scores(char names[][NAME_LEN], int scores[], int count) {
    FILE* f = fopen("scores.txt", "r");   // "r" = read: NULL if the file isn't there
    int i = 0;
    if (f == NULL) return 0;                     // first run: keep the defaults
    while (i < count && fscanf(f, "%31s %d", names[i], &scores[i]) == 2) {
        i++;                                   // fscanf returns how many values it read
    }
    fclose(f);
    return i;                                   // how many rows actually loaded
}
// Three things that will bite
C4996 , MSVC calls fopen and fscanf "unsafe" and suggests its own fopen_s. Under /WX that's a stopped build. The #define _CRT_SECURE_NO_WARNINGS line switches the warning off. It only works if it comes before the first #include.
%31s , reads one word, at most 31 characters, so it can't overflow char name[32]. One word means a name with a space in it breaks the file. Keep names to one word for now.
scores.txt , is created in whatever folder you ran the program from. If it "doesn't save", check you're running from the same folder each time. Add it to .gitignore: it's data, not code.
Predict the Output  4 drills, and one you must not run ▼
// Read the fourth one carefully
The first three run and have one right answer each. The fourth deliberately does not, and understanding why is the most useful thing on this page.
1. sizeof versus strlen, they answer different questions
#include <stdio.h>
#include <string.h>

int main(void) {
    char name[32] = "Sam";

    printf("sizeof %d\n", (int)sizeof(name));
    printf("strlen %d\n", (int)strlen(name));
    printf("%d\n", (int)sizeof("Sam"));
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
sizeof 32
strlen 3
4
sizeof asks about the box: how many bytes you reserved, known before the program runs. strlen asks about the contents: it walks forward to the first '\0' at run time. sizeof("Sam") is 4 because a string literal carries its terminator.

One trap for later: pass name to a function and sizeof in there gives the size of a pointer (8 on x64, with no warning), not 32. Passing arrays to functions covers it. That's why buffer sizes travel as a separate argument, like fgets(name, NAME_LEN, stdin).
2. What strcmp actually promises you
#include <stdio.h>
#include <string.h>

int main(void) {
    int same = strcmp("Sam", "Sam");
    int less = strcmp("Sam", "Sao");
    int more = strcmp("Sao", "Sam");

    printf("%d %d %d\n", same == 0, less < 0, more > 0);
    printf("bare if runs? %d %d\n", same != 0, less != 0);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
1 1 1
bare if runs? 0 1
The drill prints comparisons, not raw return values, on purpose. The C standard only promises the sign: zero for a match, negative if the first string sorts earlier, positive if later. MSVC usually hands back -1, 0 or 1, but other libraries don't, so == -1 is a bug waiting for a different compiler. And a bare if (strcmp(a, b)) runs when the strings differ.
3. Moving the stop sign
#include <stdio.h>
#include <string.h>

int main(void) {
    char name[8] = "Samuel";

    printf("[%s] len %d\n", name, (int)strlen(name));
    name[3] = '\0';
    printf("[%s] len %d\n", name, (int)strlen(name));
    printf("%c%c\n", name[4], name[5]);
    return 0;
}
Write your prediction down, then compile and run it.
Reveal answer 
[Samuel] len 6
[Sam] len 3
el
Nothing was deleted. The u, e and l are still sitting in the array exactly where they were, the last printf reads two of them straight out. All you did was move the stop sign, and both %s and strlen honour the first '\0' they meet and never look past it.

This is precisely what name[strcspn(name, "\n")] = '\0'; does to the newline that fgets leaves behind. It doesn't shorten the buffer. It writes a terminator over the '\n'.
4. Do not run this one
int scores[5] = { 40, 95, 12, 78, 63 };
int i;

for (i = 0; i <= 5; i++) {   // <= is the bug
    printf("%d\n", scores[i]);
}
Write your prediction down, then read the answer instead of running it.
Reveal answer
Five real numbers, then a sixth that isn't yours. There is no correct prediction for the sixth.

scores[5] is off the end. It could be another variable, leftover stack junk or a zero, and it can change between builds and between two runs of the same exe. That's undefined behaviour: the language promises nothing. A number from off the end of an array means nothing, and a bug that changes every run is worse than one that fails the same way twice.

MSVC may flag a constant index like scores[5], but it can't flag scores[i]. The loop is i < count, always.
Quiz Yourself  2 questions, answer out loud before revealing ▼
1. char name[32];, how many characters of actual text can it hold?
Reveal answer
31. The last byte has to hold the '\0' terminator or it isn't a string at all, it's just a pile of chars. This is why fgets(name, 32, stdin) reads at most 31 characters and writes the terminator itself.
2. Why does printf("Len: %d\n", strlen(name)); break your build under /W4 /WX?
Reveal answer
strlen returns a size_t, not an int, and %d expects an int, so MSVC warns C4477 (the format and the argument's type disagree) and /WX turns it into a stopped build. Fix it with %zu, the size_t format from How big a number can be, or with an explicit cast, (int)strlen(name), which is you telling the compiler "yes, on purpose."
Mixed Review  one from Phase 02, one from Phase 2.5 ▼
Two questions from earlier phases. Remembering something after a gap is what makes it stay, answer out loud first.
1. [Phase 02] int total = 7, count = 2; then float avg = total / count;, what's in avg, and how do you fix it?
Reveal answer
3.0. Both sides are ints, so the division happens in int and throws away the .5 before the result is stored in the float. Fix it by casting one side first: (float)total / count gives 3.5.
2. [Phase 2.5] A loop runs for (i = 0; i <= 10; i++). How many passes, and why does that matter more now?
Reveal answer
11, 0 through 10. With arrays, the condition is the difference between walking every box and reading one box past the end. For an array of 10, the loop is i < 10, which gives exactly 10 passes: 0 through 9.

Stuck & Curious  Functions, arrays and strings ▼
warning C4013: 'clamp_health' undefined; assuming extern returning int
You called a function before the compiler had seen it. The compiler reads your file top to bottom, once, and checks every call against what it has already read. Either move the function above main, or put a one-line declaration near the top: int clamp_health(int h);, that's a prototype, a promise that the body exists somewhere further down. Under /WX this warning is a stopped build.
My array prints garbage numbers past the last element
You went off the end. int scores[5] has indexes 0 to 4, reading scores[5] or higher reads whatever bytes happen to sit after your array, which is usually another variable or leftover junk. C does not check this for you and there's no crash to tell you. Check your loop condition: it should be i < count, not i <= count. That single character is the bug about 90% of the time.
%s printed my name and then a screenful of junk characters
Missing null terminator. %s starts at the address you gave it and prints bytes until it finds a '\0', no terminator means no stop signal, so it keeps reading memory that isn't yours. Usually you filled the buffer character by character and forgot the last byte, or you used exactly as many boxes as characters with none left for the terminator. char name[3] = "Sam" has nowhere to put it. C accepts that line without a warning, which is what makes it a trap. You need char name[4].
My strcmp check is backwards, it runs when the names DON'T match
The classic. strcmp returns 0 when the strings are equal, negative or positive when they differ, it's answering "how do these two sort?", not "are these the same?" So if (strcmp(a, b)) runs when they're DIFFERENT, because 0 is false in C and anything non-zero is true. Always write it out in full: if (strcmp(a, b) == 0) for equal, != 0 for different. Never rely on the bare call.
